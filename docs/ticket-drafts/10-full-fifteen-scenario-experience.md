# 10：交付十五題完整體驗與結果報導

## What to build

使用者能完成正式的兩幕體驗：分類排序十個價值，每槽抽一題完成十五個情境，再閱讀完整、可追溯的結果報導。續答、分享、一般重測、鍵盤及手機操作在同一正式模式中一致運作。

## Acceptance criteria

- [ ] 正式模式每槽恰抽一題，共十五題；題庫十五槽、每槽至少兩變體、共三十題，四種機制與既定價值對一致。
- [ ] 補齊完整體驗的題序、進度、返回、完成與結果導覽，不保留原型專用的三題限制或宣稱。
- [ ] 驗證內容覆蓋：十個核心價值各在預設藍圖出現三次，所有變體 ID 唯一，同槽機制一致，題意、代價及結果文案完整。
- [ ] 結果報導回顧第一幕分類排序與並列、自訂價值獨立呈現，以及十五題具體證據；同時容納相符與不同，不刻意只放大矛盾。
- [ ] 結果忠實呈現接受條件、中立及方向不明的答案，不產生第二幕總排名、名次差、強度結論、診斷或未驗證的情境依賴。
- [ ] 正式模式的重新載入續答、修改後結果、儲存失敗、清除、固定題目分享與一般重測皆遵守已定契約。
- [ ] 完整兩幕與結果套用編輯雜誌風，檢查手機閱讀、鍵盤操作、觸控尺寸及字型載入；修正跨頁不一致，而非重新引入排名表或額外機制。
- [ ] 開場告知約十五分鐘的設計目標；完整走查並記錄時間，必要時縮短文字或操作。不把設計目標寫成已實證的使用者完成時間。
- [ ] 完成端到端代表路徑、完整題庫資料驗證與建置；測試觀察外部行為，不依賴元件私有狀態。
- [ ] 不以五人試玩作為交付門檻，不宣稱已完成試玩或量表效度驗證。
