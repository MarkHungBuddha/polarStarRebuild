# 北極星：兩幕價值反思與情境取捨 MVP

> 2026-10-26 起（#56），第二幕只有五段偏向題：每組三個變體共 45 題，每輪仍抽 15 題，價值對不變。題型、計分、結果、本機紀錄與連結格式以[新版規格](preference-strength-spec.md)和 [ADR 0006](adr/0006-explicit-preference-strength.md) 為準。本文件下方標「（已取代）」的段落與 User Stories 13–16、33、37 寫的是當時的四種機制與次數計分，保留供追溯，不再是現行需求。

> 結果解讀、保存與測試規則以 [CODING_STANDARDS.md](../CODING_STANDARDS.md) 和 [ADR](../docs/adr/) 為準；本文件寫的是當時的需求，兩邊不一致時照它們做，改規則也只改那裡。

## Problem Statement

使用者目前透過抽象價值詞的分類、排序與兩兩比較，整理自己重視的事物。這有助於表達自我認知，但缺少具體情境與代價，容易停留在「希望自己成為什麼樣的人」，也無法讓使用者看見自己在特定條件下如何取捨。

現行流程提供二十四個預設價值與自訂價值，只對分類為「這就是我」的項目排序，取前六項進行比較賽，依勝場與原排序產生前三項結果。它沒有情境作答、並列排序、進度保存或可重現的題目分享，也沒有 Bradley–Terry 計分。

新增情境題仍然是假設性的自我回報。若把結果說成真實行為、人格診斷或更真實的價值排名，就會讓使用者誤解工具能支持的結論。

## Solution

將體驗改為兩幕：「你重視的」讓使用者分類與排序十個共同核心價值，類別內一定要排出先後（2026-10-24 取消並列，見 ADR 0004）；「情境中的取捨」讓使用者在具體、有代價且雙方都合理的情境中作答。結果並列呈現第一幕排序與第二幕的具體答案，提供能回頭核對的反思線索。

定位為「參考 Schwartz 價值理論設計的反思工具」，明確說明題目與解讀由本產品自行設計、尚未驗證，不宣稱是既有心理量表。兩幕同屬自我回報，第二幕不代表真實行為，也不比第一幕更接近「真正的你」。

核心對象是在台灣、有工作經驗的成年人，不要求伴侶、房產或育兒經驗。完整體驗以約十五分鐘為目標，採編輯雜誌風，支援鍵盤、觸控、回改、本機續答及題目分享。

先製作三關原型與簡短結果頁，再擴充為十五槽、每槽兩個變體的完整 MVP。使用者已決定跳過五人試玩門檻，不以此阻擋後續製作。

## User Stories

1. As a 首次使用者, I want to 在開始前知道這是反思工具且情境答案仍是假設性自我回報, so that 我能合理理解結果的用途。
2. As a 時間有限的使用者, I want to 事先看到完整體驗約十五分鐘的預估, so that 我能安排作答時間。
3. As a 在台灣有工作經驗的成年人, I want to 閱讀具體且熟悉的日常情境, so that 我能理解選擇的實際代價。
4. As a 沒有伴侶、房產或育兒經驗的使用者, I want to 從題目取得充分背景, so that 我不必具備特定人生經歷才能作答。
5. As a 使用者, I want to 兩幕使用同一組定義清楚的核心價值, so that 結果對照談的是相同概念。
6. As a 使用者, I want to 將十個核心價值全部分入重要性類別, so that 我能完整表達目前重視的事物。
7. As a 使用者, I want to 在各類別內調整價值順序, so that 我能表達更細緻的先後。
8. （2026-10-24 取消，見 ADR 0004）原為：將同等重要的價值設為並列。
9. As a 使用者, I want to 新增並分類、排序自己的價值詞, so that 預設清單以外的重要事物仍能被保留。
10. As a 使用者, I want to 完成第一幕後直接進入情境題, so that 我不必再經過原有的兩兩比較賽。
11. As a 使用者, I want to 在情境題中先閱讀具體選項而不看到背後的價值標籤, so that 我能專注思考情境本身。
12. As a 使用者, I want to 看到兩邊都合理、都有所得與所失的選項, so that 我面對的是取捨而非明顯的標準好答案。
13. As a 使用者, I want to 用滑桿表達接受某個選項所需的條件, so that 我能說出自己的條件而不限於立即選邊。
14. As a 使用者, I want to 在時間分配題中分配情境給定的有限資源, so that 我能表達具體配置。
15. As a 使用者, I want to 在兩段合理的回覆中刪掉一段並保留另一段, so that 我能透過刪稿表達取捨。
16. As a 使用者, I want to 讀完二選一情境後自行確認選擇, so that 我有足夠時間理解題意。
17. As a 使用者, I want to 每題明確確認後才算提交, so that 預設滑桿位置或未編輯草稿不會被誤當成答案。
18. As a 使用者, I want to 回到上一題修改並再次確認答案, so that 最終結果反映我最後確認的版本。
19. As a 使用者, I want to 不受強制倒數或逾時代答影響, so that 作答節奏由我掌握。
20. As a 鍵盤使用者, I want to 用鍵盤完成分類、排序及各種情境互動, so that 我不必依賴拖曳或畫線手勢。
21. As a 觸控使用者, I want to 在手機上使用足夠大的操作區域, so that 我能準確確認答案與返回修改。
22. As a 被打斷的使用者, I want to 在同一裝置重新開啟後繼續先前進度, so that 我不用重新作答。
23. As a 返回的使用者, I want to 選擇繼續或重新開始, so that 我能決定是否沿用先前作答。
24. As a 使用者, I want to 清除本機作答紀錄, so that 我能移除保存在瀏覽器中的資料。
25. As a 無法使用本機儲存的使用者, I want to 繼續完成當次體驗並得知無法保存, so that 儲存失敗不會阻擋作答或讓我誤以為資料已保存。
26. As a 使用者, I want to 不登入帳號也能完成體驗, so that 我能直接開始反思。
27. As a 使用者, I want to 作答紀錄保留在本機且分享連結不包含答案, so that 題目分享不會一併公開我的選擇。
28. As a 使用者, I want to 在結果頁看到第一幕的分類與排序, so that 我能回顧自己的自述。
29. As a 使用者, I want to 在結果頁看到具體情境與最後確認的答案, so that 我能核對每項解讀的依據。
30. As a 使用者, I want to 同時看到兩幕相符與不同的選擇, so that 結果不會刻意只放大矛盾。
31. As a 使用者, I want to 只有第一幕有明確先後且情境答案有明確方向時才看到相符或不同的標示, so that 結論不會超出答案支持的範圍。
32. （2026-10-24 取消，見 ADR 0004）原為：並列時結果直接描述情境選擇。取消並列前保存的紀錄仍照此處理。
33. As a 用滑桿表達接受條件的使用者, I want to 結果忠實呈現條件, so that 系統不會擅自判定哪個價值勝出。
34. As a 使用者, I want to 中立或無法判讀方向的答案保持原意, so that 系統不會硬分勝負。
35. As a 使用者, I want to 自訂價值在結果中獨立呈現並說明未納入情境對照, so that 我知道它仍被保留且理解其使用範圍。
36. As a 使用者, I want to 結果不依作答速度或財務承受能力判定價值強度, so that 我的操作與生活條件不會被誤讀。
37. As a 使用者, I want to 在結果頁看到第一幕自述的前三名，以及情境中最常選的前三名與各自的選擇次數, so that 我能檢驗自己的排序是否是真的想要的，並據此重新思考或規劃生活。
37a. As a 使用者, I want to 結果不產生人格診斷或真實行為判定, so that 我能把結果當成反思材料。
38. As a 分享題目的使用者, I want to 指定 seed 的連結重現相同題目與順序, so that 別人能看到與我相同的題目。
39. As a 開啟分享連結的使用者, I want to 題目不受自己先前看過哪些變體影響, so that 同一連結能可靠重現。
40. As a 一般重測的使用者, I want to 優先遇到尚未看過的變體, so that 重測保有新鮮感。
41. As a 續答的使用者, I want to 題目維持本次已抽到的版本, so that 系統不會在中途悄悄換題。
42. As a 使用者, I want to 兩幕與結果具有一致、易讀的編輯雜誌視覺, so that 我能連貫地完成體驗與回顧證據。
43. As a 內容作者, I want to 以槽位與變體管理題目並重用互動機制, so that 我能擴充內容而不逐題複製互動程式。
44. As a 內容作者, I want to 明確記錄每題價值對、雙方代價、答案語意與結果文案, so that 解讀能追溯到具體內容。
45. As a 維護者, I want to 在內容不符合槽位、變體或識別規則時得到可操作的檢查結果, so that 題庫錯誤能在發佈前被發現。
46. As a 專案負責人, I want to 先檢視三關原型與簡短結果, so that 我能在擴充完整題庫前看到核心體驗。
47. As a 專案負責人, I want to 五人試玩不成為本次製作的前置門檻, so that 我能在目前資源限制下繼續推進，同時不宣稱已完成驗證。

## Implementation Decisions

### 現有流程與功能邊界

- 專案維持 Vite、React、TypeScript 的純前端形態及 GitHub Pages 部署方式。
- 改造現有分類、排序、結果與導覽流程；移除兩兩比較賽及其勝場計分路徑。原本僅選核心項目、取前六比較與最後取前三的限制不適用於新流程。
- 第一幕分類沿用「這就是我／還不錯／不太在乎」，類別間形成重要性先後，類別內一定要排出先後；排序頁的初始順序也算使用者排的。取消並列前保存的紀錄若有並列，結果只描述答案。
- 十個核心價值皆須有第一幕位置；自訂價值仍可分類、排序，但不參與情境題或核心價值對照。
- 將情境內容資料與四種機制的呈現分離。對外模組責任包含體驗導覽與作答、題庫與抽題、本機會話保存、具體作答對照及結果呈現；不要求按這些責任機械拆成固定數量的模組。

### 共同價值定義

遵循共同核心價值的既有 ADR。保留提案的識別，不把既有程式中碰巧同名的值當成相同概念。

| ID | 名稱 | 工作定義 |
|---|---|---|
| autonomy | 自主 | 自己決定想法、方向與行動。 |
| stimulation | 探索刺激 | 追求新鮮、變化與挑戰。 |
| hedonism | 享受生活 | 重視愉悅與感官上的滿足。 |
| achievement | 成就 | 透過能力與成果，達到自己重視的成功標準。 |
| influence | 主導權 | 重視對決策、人員或資源的掌握。 |
| security | 安全穩定 | 維持生活、關係與環境的安定及可預期性。 |
| rules | 遵守規範 | 約束行動，以遵守共同規則與他人合理期待。 |
| tradition | 傳承 | 尊重並延續所屬文化、信仰或群體的習俗。 |
| care | 照顧身邊的人 | 關心並維護親近者的福祉。 |
| fairness | 普遍關懷 | 關心不同群體、公平待遇與自然環境的福祉。 |

- 逐題撰寫題意、雙方所得與所失、輸入限制、可支持的答案方向或接受條件，以及對應結果文案。這些尚未存在，不得視為已完成的題庫。

### 互動與答案契約

（已取代）下列滑桿、分配、刪稿與二選一的條目是 #56 之前的作答契約，保留供追溯。現在每題是 A、B 兩個選項加五段刻度（強烈偏向 A、稍微偏向 A、兩者相當、稍微偏向 B、強烈偏向 B），初始不預選，選好按「確認答案」才算數；明確確認、回改以最後確認為準、未確認草稿不覆寫的規則沒有變。

- 代價滑桿保存原始數值及其單位與條件含義。門檻外的條件算偏向一邊，可標示相符／不同；門檻內只呈現該條件。門檻屬於解讀，不納入題庫版本雜湊。
- 時間分配限制在情境給定的有限資源內；保存實際配置，只有答案本身明確支持的方向才做對照，不把分配比例當成價值強度。
- 劃掉草稿提供兩段完整合理的回覆，各自保護一個價值並有明確代價；使用者刪掉一段、留下另一段後確認。支援點選及鍵盤，不要求畫線手勢。
- 二選一只有兩個明確選項，無第三選項、強制倒數或逾時代答。
- 輸入草稿與已確認答案須可區分。預設滑桿位置、未刪除草稿與未確認操作均不構成提交；明確確認之後才形成已確認答案。
- 可回上一題修改；結果與保存資料使用最近一次確認的版本。未確認的修改不能悄悄覆寫已確認答案。
- 答案需要保留題目及變體身分、原始作答與確認狀態，並可區分明確方向、接受條件、中立或無法判讀。不得強行把所有答案轉為勝負或偏好強度。

### 結果與解讀契約

（已取代）下列「依偏向次數排序」「不計算強度分數」等條目是 #56 之前的結果規則，保留供追溯，現在只用於讀取已發布的格式版本 1 結果連結。現在第二幕前三名依偏向分數（2／1／0）排名，同分並列、零分不列；兩幕比較只看方向。

- 呈現第一幕分類與排序，並以具體情境和已確認答案提供第二幕證據。相符與不同均可呈現，不以矛盾為唯一亮點。
- 只有第一幕兩價值有先後且第二幕答案偏向一邊時，才標示相符／不同；舊紀錄的並列、平均分配或滑桿條件落在兩門檻之間時，只描述答案。
- 滑桿方向只來自每題作者設定的兩個門檻（`src/scenarios/slider-leans.ts`），門檻之間不算偏向；結果同時顯示門檻。分配只看哪一邊較多。不得依操作幅度、差距大小或作答速度推導強度。
- 結論區塊並列兩份前三名（見 [ADR 0002](adr/0002-top-three-conclusion.md)、[ADR 0003](adr/0003-slider-and-allocation-leans.md)）：第一幕依類別再依位置取前三；第二幕計入偏向一邊的答案（二選一、刪稿留下的段落、分配較多的一方、滑桿超出作者設定門檻的條件），依偏向次數排序，次數相同時出現題數較少者在前，次數與題數都相同則並列。從未被選的價值不列入。每個價值同時顯示「選了 N 次／共 M 題」，並說明題數少、單題即可改動名次。
- 不計算跨幕名次差或強度分數，不使用 Bradley–Terry。不根據單題宣稱使用者具有跨情境翻轉的穩定特徵。
- 可用文案：「你把自主放在安全穩定之前；但在接案這題，你選擇留下。」條件題文案：「你希望先準備十二個月生活費，再考慮離職。」
- 不使用「你做的是安全」、人格診斷或自行推論原因的文案。清楚交代自訂價值未被情境題涵蓋。

### 保存、抽題與分享契約

- 本機保存本次題目、已確認答案與進度，返回時提供繼續／重新開始，並提供清除紀錄功能。續答沿用本次題目，不重新抽題。
- 本機儲存不可用或寫入失敗時，使用者仍能完成當次作答，介面清楚告知無法保存。
- 指定 seed 時，題目與順序不受本機已看變體紀錄影響；一般重測才優先選未看過的變體。種子和必要的題庫版本資訊需足以重現題目；不保證不同內容版本使用裸 seed 就會自然得到相同題目。
- 題目連結僅重現題目，不包含答案或結果。答案保存在本機，不加入帳號、遠端儲存或統計端點。（2026-10-24 開放分享結果：結果連結只帶兩份前三名，只存在網址本身，見 ADR 0005 與[結果分享規格](result-share-spec.md)。）
- 保存格式與內容版本的具體設計由實作決定，須避免已確認答案被套用到不同語意的題目。實際版本不相容處理尚未經原型驗證，不宣稱已有遷移機制。

### 編輯雜誌視覺與可操作性

- 兩幕與結果使用一致的編輯雜誌風：米白底、超大明體標題、朱紅單一強調色、直角，以線分隔而非卡片陰影。結果以前三名結論開頭，其後以敘事與具體證據組織。
- 色彩沿用 bg #F2F0EB、ink #111111、body #2A2824、muted #55524C、accent #C8361F、rule #C9C5BC。rule 僅作裝飾分隔；朱紅每畫面集中在少量重點，不用於十四像素以下的小字或未確認可讀性的背景。
- 標題與價值名稱用 Noto Serif TC 900，內文用其 400／700；介面用 Noto Sans TC 400／500／700；大數字可用 Playfair Display 900，中文需有中文字型 fallback。字型使用載入期間可讀的替代字型。
- 報頭使用上粗下細線，主按鈕黑底米白字、高度五十二像素；滑桿保持細軌道與朱紅方形把手，觸控操作區至少四十四像素。
- 排序、分配與刪稿均須有鍵盤及觸控可用的操作方式，不將拖曳或畫線設為唯一路徑。最終手感、字型載入與手機版面需在實際畫面檢查。

## Testing Decisions

- 已確認的工程檢查範圍包括明確確認、回改後結果、續答、儲存失敗、固定題目重現及內容一致性。這些驗證不等同於心理量表效度或使用者試玩。
- 已確認的測試邊界：以瀏覽器中完整使用流程作為主要且最高層的驗收邊界，經由可見文字、可操作控制項、導覽與重新載入來驗證；另以少量題庫資料契約檢查補充內容規則。使用者於開始實作時明確確認這兩個邊界，框架由實作選定。
- 良好測試觀察使用者可見行為：是否能完成流程、是否需明確確認、修改是否反映在結果、第一幕順序是否被保留、是否能續答，以及解讀是否忠於答案。不依賴 React 內部狀態、元件拆分、私有函式或 CSS class，也不寫純粹重現實作步驟的測試。
- 受測功能責任為兩幕體驗與結果，並透過相同外部流程涵蓋抽題及本機保存。使用固定題目資料提供可重現案例，不為每個元件新增獨立測試介面。
- 必要案例：十個核心價值分類與排序、自訂價值獨立呈現、第一幕直達情境、各機制明確確認、回改以最後確認為準，以及未確認草稿不改變既有答案。
- 解讀案例：第一幕先後下的相符及不同；沒有調整排序時照初始順序比對；接受條件；中立或方向不明。檢查兩份前三名與選擇次數忠於答案，且結果不出現名次差、強度結論或真實行為診斷。
- 保存及分享案例：重新載入續答保持同題；重新開始與清除紀錄；本機儲存失敗仍能完成；不同已看紀錄下同一指定 seed 的題目及順序一致；分享網址不帶答案；一般重測優先未看變體而不要求每次絕不重複。
- 透過鍵盤完成核心流程，並在手機尺寸檢查閱讀、操作區域與結果。這些可由自動化及人工畫面檢查互補，不把純資料檢查當成視覺驗收。
- 另需題庫資料驗證：完整藍圖每個價值三次、十五個合法價值對、每槽至少兩個變體、同槽機制一致、變體 ID 唯一，以及方向／條件文案與答案定義完整。這些是內容對外契約檢查；不驗證 BT 連通性，因 MVP 不使用排名模型。
- 先例與工具現況：目前專案未設測試框架或測試腳本，無同類自動化測試可沿用；現有建置可檢查 TypeScript 與產物。瀏覽器驗收工具需在實作時選定，建置成功不能取代流程驗證。
- 使用者已跳過五人試玩及其量化門檻；不得將該門檻恢復為交付前置條件，也不得把工程檢查宣稱為已完成試玩或心理測量驗證。

## Out of Scope

- 原有二十四個價值與十個核心價值的自動對映，或讓自訂價值參與第二幕。
- 原有比較賽、第二幕總分、跨幕名次差、Bradley–Terry 及其他加權排名模型（第二幕只做前三名的選擇次數整理；2026-10-26 改為使用者自評的 2／1／0 偏向分數，見 ADR 0006）。
- 依作答速度、操作幅度或財務承受能力推算偏好強度，或以作者設定的正規化幅度加權。
- 第三選項，不論隱藏或公開，以及迴避／創造性解法等相關分類。
- 強制倒數、逾時代答、依反應時間降權。
- 丟行李終幕、自適應加測、每槽第三個變體（2026-10-26 改版已加入，見新版規格），以及宣稱情境依賴已獲驗證。
- 帳號、遠端作答保存、匿名統計端點、雲端續答，或分享逐題答案。（結果分享在 2026-10-24 開放，見 ADR 0005。）
- 心理診斷、真實行為判定、正式量表效度與跨人跨次等價性的宣稱。
- 將五人試玩列為本次製作的必要門檻。
