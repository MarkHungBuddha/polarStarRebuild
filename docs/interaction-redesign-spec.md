# 第二幕六種互動改版

狀態：2026-10-26 完成 Grill 與六題試玩確認；專案負責人已確認本版測試接縫，以及 12 張子票的拆票與依賴，依此發布 GitHub 父 issue 與子票。不開始 45 題實作。發布編號與實際狀態記於工作流程 tracker。

本次規格在正式整合完成後，取代 [現行互動情境題規格](interactive-scenario-spec.md)中「45 題只用三種互動」的限制。其他未在此修改的產品約定沿用現行規格。舊規格與既有上線紀錄保留，不追改為本次設計。

## Problem Statement｜問題

目前雖有選方案、分配與調整三種資料型別，分配和調整共用逐格選兩側的介面，實際玩起來只有兩套主要操作。旅行六天的安排，也變成六次選 A／B，沒有操作行程的感覺。

## Solution｜解法

改版以「操作情境中的物件，看到安排與代價跟著改變」為標準。互動方式從題目的決策內容出發，不把同一套選項換成不同外觀。必要時可重寫情境，保留該組原本探討的價值取捨。

## Implementation Decisions｜實作決策

### 已確認的範圍

- 保留十個核心價值、15 組價值取捨，每組三個情境變體，共 45 題；每輪仍抽每組一題，共 15 題。
- 第一幕的分類、排序與自訂價值流程沿用現行設計。
- 六類操作是設計起點，不設平均分配題數，也不把六類視為永久上限。每個情境選適合的機制；同類可重複使用，但操作物件、限制與回饋須符合題意。
- 保留手帳風格。滑鼠與觸控可拖曳，鍵盤和不方便拖曳的人也能完成相同決策。
- 先完成六類各一題試玩，再展開到 45 題。六題試玩已完成並獲確認；其餘題面須另行審閱。
- 正式作答仍無倒數、反應速度評分、手速要求或自動提交。操作時不揭露價值對應、不給好壞評語。

### 六種操作

| 類型 | 使用者做什麼 | 即時回饋與紀錄 |
| --- | --- | --- |
| 拖拉排程 | 把活動放入時段，移動、交換或撤回 | 顯示每個時段的安排與剩餘空位，紀錄具體時段，不只留兩側總數 |
| 物件分配 | 將同種有限資源分到不同用途，再移回或重分 | 顯示各處物件、數量及未分配資源，紀錄每件資源的去向 |
| 場景拖曳 | 移動人物或物件進入情境中的位置 | 位置對應明確行動，場景與後果改變；未落在有效位置不視為決策 |
| 多句刪稿 | 在完整草稿中劃掉、還原任意多句，再傳送或決定不傳 | 即時呈現保留的全文與句數；紀錄留下哪些句子及是否傳送 |
| 排序取捨 | 重新排列物件，在有限容量內保留一部分，延後其餘 | 明示容量、已保留與延後內容；紀錄完整順序及保留範圍 |
| 連動調整 | 拖時針、翻桌曆或調整具體條件 | 刻度、單位與影響一起改變，紀錄原始單位與安排；不能只做抽象偏向滑桿 |

### 刪稿的完整行為

參考已試玩的「想說的話」。沿用同一個訊息泡泡逐句劃掉／還原的手感，題材依北極星的價值取捨改寫。

- 開始呈現完整草稿，每句獨立切換；允許刪掉多句、保留多句、全部保留及全部刪除。
- 不預設只能刪一句，不限定保留幾句，句數由題材決定，不固定為七句。
- 已刪句子留在原位，以刪除線等方式呈現，方便還原。鍵盤焦點需清楚可見。
- 即時顯示會傳出的句數，能預覽保留全文。不是將兩個立場各拆成幾句，再強迫只留一個立場。
- 有保留內容時按「傳送這段訊息」確認；全部劃掉時按「這次不傳」確認。
- 全留直接確認是有效決策。全刪只代表這次不傳，不自動等同「目前無法決定」。
- 確認後的紀錄包含送出的全文或不傳的決策；重新開啟修改時還原原本保留與刪除的句子。
- 不沿用參考遊戲的焦慮／迴避分數。麥克風隱藏結局等未經本次確認的機制不在範圍內。

### 草稿、撤回與確認

- 操作過程是草稿，只有明確確認才更新答案。修改尚未確認時，結果、續答與分享仍使用上一份已確認答案。
- 每題可撤回最近一步、重設草稿、返回修改；能回到已確認安排，再調整後重新確認。
- 有初始安排的題目，提供明確的維持操作，不把未操作的預設值當成答案。刪稿的完整草稿可用明確傳送表示全留。
- 可明確選擇「目前無法決定」再確認，與尚未作答、平均分配及不傳訊息分開記錄。
- 拖曳與替代操作產生相同安排。先選物件、再選目的地能完成放置；排序另可上下移動，連動控制支援鍵盤並保留單位。
- 觸控與鍵盤能完成整輪，320px、390px 與桌面版面可閱讀且無橫向溢出，淺色及深色模式一致。

### 結果怎麼整理

先保留每題具體決策，再判斷是否有可解讀的方向。不得為了湊出價值排名，把所有操作硬轉成兩側勝負。

- 明確行動選定一側，或同種可比較資源分給一側較多時，每題最多記該價值一次；平均分配不加次數，差距不加權。
- 排序題只有在容量內的內容形成可比較資源分配時，才依該分配判方向；排序名次差不代表偏好強度。
- 場景使用明確位置／行動的語意，不以拖動距離、路徑或手速推定價值。
- 刪稿先引用保留全文。多句同時表達不同考量，或沒有事先可說明的決策規則時，保留原始決策、不判方向；不按刪了幾句計分。
- 條件調整保留原始數值與單位；不能用任意門檻推定哪個價值勝出。固定同種資源的分配則依該分配整理。
- 全刪、不傳、混合考量、條件回報及無法決定都要忠實呈現，不能一律改寫成同一種未決定狀態。
- 第一幕與第二幕仍並列，只對方向明確的題目做一致／不同對照。同次數並列、0 次不排名，不產生人格或診斷結論。
- 顯示「明確決策 N / 15 題」，說明未計數也可能是保留具體決策但不判方向，不能仍宣稱所有未計數題都只有平均或無法決定。
- 結果保留全部 15 題的可追溯紀錄、返回修改、自願反思與自訂價值的既有行為。六題原型各價值出現次數不同，不用它生成完整十價值排名。

### 續答與版本

- 已確認的資料須能重建每個時段、物件去向、排序、刪句及連動安排；只保存兩側總數不足以重建時，不得假裝還原原始安排。
- 本機保存、重新開啟、回到結果修改、重新開始與清除紀錄皆支援六類答案。未確認草稿依現行規格不持久保存。
- 舊題面或舊型別的答案不得直接套到新題。可沿用的第一幕資料保留，使用者看到改版說明後決定繼續或重新開始。
- 題庫版本隨內容與結構更新。舊題目連結無法重現時要說明原因；舊結果按分享當時的格式與規則呈現，不重算、不偷偷換題。
- 是否需新的結果連結格式版本由實作依資料語意判斷；若欄位或解讀契約改變，必須新增版本並保留舊版讀取，不能為沿用版本號而改寫舊意義。
- 結果圖、結果連結、收件者頁與本機結果一致。維持目前分享範圍；逐題安排、完整訊息與反思留在本機，不放進公開分享資料。

### 45 題展開與審閱

題目 registry 仍按第 1–5、6–10、11–15 組分三批維護。新內容是 AI 草稿，須記錄價值配對、選用機制、資源限制、雙方代價、方向是否可判，以及待審閱事項。

每題都要有完整可操作的情境，不以空白元件、僅換控制項、或待補題面當作完成。三批共 45 題均可從本機清單直接開啟、逐題確認與重測；六題原型的通過不替代其餘內容審閱。全部內容經專案負責人確認、整合驗收完成後才切換正式入口。

### 模組與整合方式

- 在既有作答流程、題目 registry、答案檢查、結果整理、本機保存、題目連結與結果分享模組內擴充六類資料與行為。第一幕沿用現行介面。
- 題目資料負責定義物件、有效位置、容量、單位、限制與可說明的方向規則；共用互動元件依資料呈現，不在元件內逐題特判。
- 答案契約保留可重建的原始決策與明確的無法決定狀態；結果整理從已確認答案取得具體證據，再決定是否可計次。
- 第一張完整作答票引入六類型別的擴充位置、答案檢查與結果整理介面，以及共用瀏覽器作答輔助；後續機制各自擴充，不另開只交付型別或元件的架構票。
- 開發與審閱路徑先承接完整作答切片，現行正式入口維持可用；45 題與版本、分享整合完成後才正式切換。
- 本規格在六類操作與不判方向的決策上，取代現行內容筆記中「僅有兩側選項／逐格操作」「刪稿只留一段」及「條件題一律改成選邊」的限制。其餘關於價值定義、雙方代價、避免道德壓力與 AI 草稿審閱的原則沿用。正式切換時同步更新適用文件，保留歷史版本的說明。

## Testing Decisions｜測試決策

專案負責人於 2026-10-26 確認沿用既有兩種接縫，不新增內部 state 或函式測試入口：

1. **主要接縫：瀏覽器使用者流程。** 從第一幕、情境操作、確認到結果、返回修改，再到重新開啟續答與獨立收件者頁。透過可見安排、全文、次數與說明驗證使用者得到的行為，不斷言元件實作或內部答案結構。
2. **補充接縫：小型題庫契約。** 檢查 15 組 × 3 變體、固定價值配對、唯一識別、registry 次序與版本，以及各機制必要的資源、位置、容量和單位資料；不在這層測 UI 操作。

### 測試範圍與既有做法

- 六類操作各以完整情境驗證有效／無效操作、邊界、撤回、重設、明確維持、無法決定、確認、返回修改及原始紀錄。比對拖曳、點選與鍵盤的可見決策，不用動作次數推論正確性。
- 結果流程沿用既有「以題目標題作答、展開決策紀錄、修改該題」的輔助方式。驗證均分、方向明確、不傳、混合考量、條件回報、全部無方向、同次數並列與 0 次不排名；不依抽題位置寫死測試。
- 續答與遷移沿用既有實際作答後重新整理／續答的流程。損壞或舊版紀錄使用不透明範例，不按目前內部 session 結構拼裝資料；舊題不相容、讀寫失敗與清除都驗證可見告知及使用者選擇。
- 分享沿用既有本機結果與獨立瀏覽器收件者結果比對、結果圖檢查及定版舊連結範例。格式版本 1、2、3 的已發布範例只增不改，仍照原義顯示；新版不判方向的說明不能回寫舊版規則。
- 題庫契約沿用現有藍圖與內容檢查，更新六類適用條件，不把舊型別限制原樣加在新機制上。
- 320px、390px 與桌面、深淺色、觸控和鍵盤，使用既有版面、文字裁切與觸控目標檢查輔助，並完成實際走查；不能只測 CSS 尺寸便宣稱觸控通過。
- 各票跑相關檢查，整合後依專案流程跑型別、程式碼、建置及完整端到端檢查，保留本機與 CI 的真實結果。原型的測試紀錄僅適用原型，不代表正式實作通過。

### 完成條件

1. 第一幕後可完整完成 15 題與結果；45 個變體都可直接測試，不遺漏任何價值組或變體。
2. 六類均有實際用途，不把分配與調整再次統一成逐格選兩側；每題的物件與回饋貼合情境。
3. 刪稿支援多句、全留、全刪、不傳與還原；紀錄正確，沒有強迫二選一。
4. 草稿、撤回、確認、修改、續答、清除與版本隔離在六類上行為一致。
5. 排名及逐題對照只使用有語意依據的決策；方向不明時保留原始資料及說明。
6. 分享結果與本機一致，舊結果仍可讀取，分享資料不新增完整訊息或反思等私密內容。
7. 手機、桌面、觸控、鍵盤、淺色及深色均完成實際走查，依專案規定通過型別、程式碼、建置與相關端到端檢查。
